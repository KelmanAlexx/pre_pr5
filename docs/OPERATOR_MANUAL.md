# Руководство оператора АРМ — модуль «Общежития»

## 1. Назначение

Модуль используется оператором для просмотра сведений об общежитиях и проверки адреса здания. Данный документ описывает учебный API-пример. В реальной системе вход выполняется через корпоративную учётную запись и настроенный механизм авторизации.

## 2. Начало работы

1. Включите рабочее место и подключитесь к сети организации.
2. Откройте адрес системы, который сообщил системный администратор.
3. Войдите под своей учётной записью.
4. При отсутствии доступа обратитесь к администратору, не пытайтесь использовать чужую учётную запись.

## 3. Просмотр общежитий

Для получения списка отправляется GET-запрос на `/api/dormitories`. В ответе отображаются идентификатор, название общежития и адрес здания.

## 4. Создание записи

Создание выполняется уполномоченным сотрудником. Необходимо указать название общежития и полный адрес. После сохранения система создаёт запись здания и связывает её с общежитием.

Пример данных:

```json
{
  "name": "Общежитие № 1",
  "address": "Сызрань, улица Приморская, дом 67"
}
```

Перед сохранением проверьте правильность адреса. Не создавайте повторную запись, если запрос долго выполняется: сначала обновите список и убедитесь, что запись не появилась.

## 5. Действия при сбоях

- **Страница или API не открывается:** проверьте сеть и повторите попытку через короткое время.
- **Ошибка 400:** проверьте, что название и адрес заполнены.
- **Ошибка 404:** проверьте идентификатор записи.
- **Ошибка 500:** запишите время ошибки и текст сообщения, если он отображается; передайте сведения администратору.
- **Данные отображаются неверно:** не исправляйте базу самостоятельно, сообщите ответственному сотруднику.

## 6. Запрещённые действия

Оператор не должен самостоятельно менять конфигурационные файлы, запускать SQL-скрипты, удалять резервные копии или устанавливать обновления.
