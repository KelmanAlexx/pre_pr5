# Инструкция системного администратора по обновлению

## 1. Общие положения

Обновление выполняется по заявке Change Request. Для учебного релиза используется версия v1.9.0 и задача CAMPUS-108. Работы выполняются в согласованное окно обслуживания.

## 2. Схема доставки

Используется Canary Deployment: новая версия сначала запускается на одном экземпляре или небольшой части АРМ/серверных экземпляров. После проверки обновление распространяется на остальные узлы. Для клиентского ПО пакет должен скачиваться с центрального сервера по HTTPS, проверяться по контрольной сумме и цифровой подписи, а установка выполняться от имени сервисной учётной записи.

Для серверной части в Kubernetes применяется Deployment. Перед обновлением сохраняется предыдущий образ контейнера, а rollout status используется для контроля готовности. Blue-Green может применяться, если инфраструктура позволяет держать две среды одновременно и переключать трафик через Service.

## 3. Резервное копирование

Перед обновлением:
1. Остановить запись в локальную БД на время копирования либо использовать согласованный механизм SQLite Backup API.
2. Скопировать `appsettings.json` и остальные конфигурационные файлы в каталог резервной копии с ограниченными правами.
3. Скопировать локальную SQLite БД и каталог кэша.
4. Для PostgreSQL создать дамп, например `pg_dump -Fc -d smart_campus -f campus_before_v1.9.0.dump`.
5. Проверить, что файлы резервной копии существуют и имеют ненулевой размер.

Не хранить пароли и ключи в открытом виде в общем каталоге или Git.

## 4. Установка

1. Проверить номер версии и источник пакета.
2. Проверить SHA-256 и цифровую подпись пакета.
3. Создать резервную копию.
4. Выполнить `sql/01_expand.sql`.
5. Установить новую версию на Canary-узел.
6. Проверить работоспособность, затем выполнить `sql/02_migrate.sql`.
7. После успешной проверки обновить остальные узлы.
8. Запустить Sanity Test и записать результат в журнал релиза.

## 5. Проверка обновления

- Сервис отвечает на `/health`.
- API возвращает список общежитий.
- Создание тестовой записи проходит успешно.
- У записи заполнен `BuildingId`.
- Адрес читается из `Buildings`.
- В логах нет критических ошибок.
- Тестовая запись удалена после проверки.

## 6. Откат

Для Kubernetes:

```bash
kubectl rollout undo deployment/campus-api
kubectl rollout status deployment/campus-api
```

При файловом обновлении учебной утилитой:

```bash
dotnet run --project updater/CampusUpdater.csproj -- rollback ./backup ./app
```

При откате приложения расширенная схема БД сохраняется. Нельзя запускать `03_contract.sql`, пока предыдущая версия приложения ещё использует `Dormitory.Address`.

## 7. Завершение

Записать версию, дату, ответственного, результат проверок и замечания в журнал изменений. Сообщить операторам об окончании работ.
